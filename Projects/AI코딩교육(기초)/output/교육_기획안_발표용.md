# AI 기반 Vibe Coding (초급) 교육

> 말로 요청하고, 실행해 보고, 내 업무에 맞게 고치는 첫 한 시간

- 일정: 2026년 9월 29일(화), 16:00–17:00 / 총 60분
- 대상: 코딩 경험이 없거나 AI 코딩을 업무에 활용하려는 입문자
- 방식: 핵심 개념 설명 + 강사 시연. 설치를 동시에 진행하는 실습은 제외
- 기준 자료: 사용자가 선택한 `기획안_원안 copy.md`
- 핵심 메시지: 업무를 아는 사람이 입력·처리·출력·확인 기준을 설명하면, AI와 함께 작은 업무 도구를 만들고 개선할 수 있다.

## 교육 목표

1. Coding Agent가 허용된 도구와 권한 안에서 파일을 찾아 수정하고 실행하는 흐름을 이해한다.
2. 프로그램의 역할과 개발 도구의 용도를 감각적으로 구분한다.
3. 원하는 결과와 실제 결과를 비교하며 추가 수정을 요청할 수 있다.
4. AI로 코드를 만드는 것과 프로그램에서 AI API를 호출하는 것을 구분한다.

모든 용어와 문법을 외울 필요는 없다. 모르는 개념은 AI에게 쉬운 설명과 예제를 요청하고, 실행 결과로 확인하며 배운다.

## 1. 왜 AI 코딩인가? (8분 / 16:00–16:08)

- Vibe Coding: 자연어로 의도를 설명하고 AI와 코드를 만들고 수정해 나가는 방식으로 소개한다.
- 업무 담당자는 목표, 예외, 성공 기준을 제공한다. AI는 코드 작성·파일 수정·실행·오류 탐색을 돕는다.
- 일반적인 텍스트 질의응답과 Coding Agent의 차이를 실제 파일 변경으로 보여준다. 챗봇도 실행 도구가 연결될 수 있으므로 제품 이름만으로 구분하지 않는다.
- 도입 시연: “완료된 업무를 숨기는 버튼을 추가하고 동작을 확인해줘.”
- 컴퓨터 제어 범위는 연결 도구와 권한에 따라 달라진다. GUI·마우스 제어는 지원 환경에서만 선택적으로 보여준다.

## 2. AI 코딩에 필요한 기초 (12분 / 16:08–16:20)

- 대표 구조: 사람 ↔ 프론트엔드 ↔ API ↔ 백엔드 ↔ DB 또는 파일
- 프론트엔드: HTML은 구조, CSS는 모양, JavaScript는 동작을 담당한다.
- 백엔드: 요청에 따라 자료를 읽고 계산하고 저장한다. Python은 구현 언어의 한 예다.
- 작은 웹 도구는 브라우저만으로도 시작할 수 있다. 웹 앱도 배포·운영·호환성 관리가 필요하다.
- 프론트엔드와 백엔드 모두 요구사항·예외·검증이 중요하다. “백엔드는 답이 명확해 AI가 잘한다”라는 단정은 쓰지 않는다.
- 라이브러리: 미리 만들어진 기능. 가상환경: 프로젝트마다 패키지와 버전을 분리하는 환경.
- 터미널과 CLI: 문자 명령으로 작업하는 창과 방식. PowerShell 예시로 `pwd`, `dir`, `cd ..`, `cls`, `ipconfig`를 보여준다.
- Git은 변경 이력 관리, GitHub는 원격 저장과 협업 서비스다.
- 환경변수는 코드 밖에서 설정을 전달하는 방법이다. 자동 암호화 저장소는 아니다.
- 모델 선택: 원안의 GPT-5.6 Luna·Terra·Sol을 속도·비용·작업 복잡도 관점에서 비교한다. 전체 모델 목록을 뜻하지 않는다.
- 추론 노력: 기본값에서 시작해 필요할 때 높인다. 명칭과 지원 범위는 모델·클라이언트에 따라 다르다. Ultra는 여러 에이전트를 활용하는 모드라는 점을 구분한다.
- Artificial Analysis는 참고 자료로 소개하며, 실제 업무 예제의 결과와 함께 판단한다.

## 3. 프로그램 제작 시연 (17분 / 16:20–16:37)

### 관통 예제: 업무 요청 요약기

- 입력: 담당자·업무·상태가 있는 가상 CSV 6건
- 처리: 완료가 아닌 업무를 추출하고 담당자별 미완료 건수를 집계
- 출력: 브라우저에서 읽는 HTML 보고서
- 확인 기준: 전체 6건, 완료 2건, 미완료 4건. 미완료는 민지 2건·준호 1건·서연 1건

### 진행 순서

1. 입력·처리·출력·확인 기준을 포함한 요청을 전달한다.
2. VS Code에서 파일, 코드·변경 내용, 터미널, Agent 대화 영역을 짚는다.
3. Python 프로그램을 만들고 실행해 HTML 보고서를 확인한다.
4. “완료 숨기기”와 “담당자 필터”를 추가하고 결과를 확인한다.
5. 누락 열 오류를 보여주고, 기대한 결과·실제 결과·오류 메시지를 함께 전달한다.
6. 원본 보존, 결과 위치, 확인 방법 같은 공통 지침을 AGENTS.md에 정리하도록 요청한다.

라이브 생성이 지연되면 제공한 완성 예제와 덱 내부의 로컬 데모를 사용한다. 덱 내부 데모는 실제로 필터가 동작하는 HTML 예제이며, 실시간 AI 코드 생성이나 사내 시스템 연동 화면은 아니다.

## 4. 개발 도구와 시작 환경 (9분 / 16:37–16:46)

- 도구 경로: 전용 앱, VS Code 확장, CLI. 강의는 VS Code + Codex 확장 기준으로 설명한다.
- Cline, Kilo Code, Claude Code는 대안 도구로 간단히 소개한다.
- Python은 이번 CSV 처리 예제에 필요하다. VS Code·Codex 확장으로 파일과 작업 흐름을 확인한다.
- Python 확장, Korean Language Pack, 색상 테마는 용도에 따른 편의 설정이다.
- Node.js는 npm 설치 경로나 JavaScript 개발 시 필요하다. Git은 변경 이력 관리에 사용한다.
- Codex CLI: 공식 안내의 허용된 설치 경로 선택 → 프로젝트 폴더 이동 → 실행·로그인 → 모델·권한 확인.
- Full Access는 접근 범위를 넓히는 설정으로 설명한다. 샌드박스의 작업 범위와 승인 정책을 구분한다.
- 원안의 사내 전용 앱 사용 제약을 전제로 하되 현재 허용 도구·설치·로그인 방법은 사내 안내로 확인한다.

## 5. 사내 AI 프로그램과 P-GPT (9분 / 16:46–16:55)

- AI로 프로그램을 개발하는 것과 실행 중 AI API를 호출하는 것을 구분한다.
- 기본 집계는 LLM 없이 실행 가능하다. 자연어 요약 같은 추가 기능에 AI API를 연결할 수 있다.
- API는 요청·응답의 약속, API Key는 인증 정보다. 키는 HTML이나 공개 저장소가 아닌 서버 측 설정에서 관리한다.
- 사내 준비: 신청 경로·담당자, API 주소·인증 방식·모델, Responses 지원 여부, 사내망·프록시·CA·사용 한도 확인.
- Responses API 예제는 공개 OpenAI API의 개념 예시로 제시한다. P-GPT 호환성이나 실제 호출 성공으로 표현하지 않는다.
- 연결 오류는 인증, 인증서, 주소·망·프록시 문제로 나누어 살펴본다. 인증서 검증 해제를 기본 해결책으로 안내하지 않는다.

## 6. 마무리와 질의응답 (5분 / 16:55–17:00)

- 첫 과제: 매주 반복하는 작은 업무 하나를 고르고 입력·처리·출력·확인 기준을 적는다.
- 학습 습관: 작은 요청 → 실행 → 결과 확인 → 추가 요청.
- 질문 및 다음 시도 안내.

## 발표 자료와 운영 준비

- 본문 29장 + 부록 3장. 본문 14장에 3회의 단계 노출이 있다.
- HTML은 1920×1080 고정 무대, 키보드·클릭·스와이프·목차·발표자 노트를 제공한다.
- AI 생성 삽화 4종, 역할 구조도, 파일 처리 흐름, 개발 화면 배치도, 로컬 인터랙티브 예제를 사용한다.
- 그림·서체를 HTML에 포함한다. 공식 문서 링크를 열 때는 인터넷이 필요하다.
- 백업 PDF, 발표자 노트, Python 완성 예제, 정상·오류 입력 검증 결과를 함께 제공한다.

### 강의 전 사내 확인 필요

- P-GPT 실제 신청 링크·승인 담당자·호출 규약·모델·사내 CA 적용 방법
- 사내에서 허용된 도구·설치·로그인·네트워크·자료 사용 범위
- 실제 강의 PC의 도구·모델 목록과 시연 실행 여부

이 항목은 제공 자료만으로 확인할 수 없어 임의로 채우지 않았다.
