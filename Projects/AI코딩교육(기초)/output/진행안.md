## 초반 체험

2~3장은 VS Code의 파일 탐색기, 코드 편집기, 변경 내용, 터미널, Codex 대화 패널을 함께 보여주는 개발 체험입니다. 실제 모델 호출이나 셸 실행 없이 작업 과정을 재현하며, 테트리스는 충돌·회전·줄 삭제·점수 계산을 실제로 수행합니다.

2장에서 첫 요청을 보내면 회색 블록과 작은 점수만 있는 투박한 첫 버전이 나타납니다. 자동 플레이는 처음부터 켜져 있고, 기본 낙하 간격은 40ms입니다. 기존 예제의 160ms보다 빠릅니다. 일시정지와 새 게임을 사용할 수 있습니다.

3장에서는 같은 게임 상태를 유지하면서 다음 요청을 하나씩 보냅니다. 준비된 요청을 선택하면 Codex 입력란에 들어가고, 전송하면 대화·파일 변경·실행 결과가 함께 갱신됩니다.

1. 블록마다 색을 다르게 하고 화면을 게임답게 꾸미기: 단색 화면에서 컬러 블록과 어두운 게임 화면으로 변경.
2. 점수를 크게 하고 다음 블록 보여주기: 큰 점수판과 다음 블록 미리보기 추가.
3. 착지 위치와 줄 삭제 효과 넣기: 고스트 블록, 줄 삭제 강조, 점수 효과, 1~5배속과 직접 조작 기능 표시.

직접 입력한 요청도 위 기능과 속도 조정 범위에서 처리합니다. 지원하지 않는 요청은 안내하고, 실제 AI가 자유롭게 구현한 것처럼 표현하지 않습니다. 2장에서 제작 요청을 다시 보내면 개선 단계를 초기화하여 체험을 반복할 수 있습니다. 새 게임 버튼은 게임판만 초기화하고 개선 내용은 유지합니다.

자동 배치와 충돌·줄 삭제의 기본 접근은 기존 `output/build/plan2.js`를 계승했습니다. 업그레이드에는 7종 블록을 한 묶음으로 섞는 방식, 다음 블록, 회전·하드 드롭, 게임 종료 상태, 비활성 장에서의 게임 정지를 포함했습니다.

화면 배치와 작업 흐름은 [공식 Codex IDE 안내](https://learn.chatgpt.com/docs/codex/ide)를 참고했습니다. 실제 VS Code와 Codex 화면은 버전·설정에 따라 다르며, 발표 화면은 교육용으로 글자와 배치를 조정한 재현입니다. 편집기의 코드는 핵심 설정을 발췌해 보여줍니다.

가능성을 보여준 다음 “사람이 무엇을 보고 수정했는가”로 연결합니다. 초급 체험이 복잡한 업무를 곧바로 구현할 수 있다는 의미로 받아들여지지 않도록, 6장에서 지식과 안목의 역할을 설명합니다.

## 5장 · 세 파일에 걸친 테트리스 기능 추가

이번 요청은 “다음 블록 미리보기, 착지 가이드, 줄 삭제 효과를 넣어줘”입니다. 글자 크기 변경 사례를 대체했습니다. 한 번에 한 방식만 넓게 보여주고, 오른쪽 아래 버튼 하나로 각 단계를 진행합니다.

챗봇은 요청 → 세 파일의 코드 답변 → 코드 복사 → HTML/CSS 적용 → 게임 로직의 연결 위치 찾기 → 함수 연결 → 실행 확인의 7개 장면입니다. 핵심은 함수를 붙여 넣는 것만으로는 작동하지 않고, 게임의 그리기와 줄 삭제 처리에서 해당 함수를 실행하도록 연결해야 한다는 점입니다. 코드 화면은 핵심을 발췌한 교육용 재현입니다.

이어서 에이전트는 같은 요청 → 관련 파일·함수 확인 → 세 파일 수정 및 연결 → 실행 확인의 4개 장면을 보여줍니다. 버튼은 작업을 설명하는 장면 전환이며, 제품이 매 단계마다 승인을 요구한다는 의미는 아닙니다. 마지막 버튼은 처음부터 다시 보여줍니다. 장을 오가도 단계는 유지됩니다.

첫 장면과 두 완성 장면의 테트리스는 실제 충돌·줄 삭제 엔진으로 자동 플레이합니다. 완성 장면에는 다음 블록, 실제 충돌 위치의 윤곽, 줄 삭제에 맞춘 빛·점수 효과가 표시됩니다. 기본 낙하 간격은 35ms이며, 다른 장과 백그라운드에서는 정지합니다. 감소된 모션 설정에서는 정적인 게임 상태를 표시합니다. 2~3페이지 게임 상태와는 독립적입니다.

실제 외부 AI 호출이나 PC 파일 변경은 없습니다. PDF에는 두 작업 과정과 기능별 연결 지점을 정리합니다.

## 10분 실제 제작

15장에서 실제 사용 가능한 코딩 에이전트 환경으로 전환합니다. 이 발표 HTML 자체에는 에이전트 실행 기능이 없습니다. 15장 한 장에 제작 흐름을 모았습니다. 제작 소재는 현재 순위 도구이며, 다른 소재로 교체 제안 중입니다.

1. 1분: 입력과 기대 결과를 소개합니다.
2. 4분: HTML 한 파일로 작동하는 작은 순위 도구를 실제 에이전트에 요청합니다.
3. 2분: 파일을 브라우저로 열고 정상 입력을 확인합니다.
4. 2분: 공동 순위, 누락 처리, 80점 강조, 정보 배치를 수정합니다.
5. 1분: 정상 입력과 예외 입력을 다시 확인합니다.

기존 16~17장의 제작 사례는 삭제했습니다. 별도 브라우저에서 열 수 있는 `demo/ranking-first.html`, `demo/ranking-complete.html`도 제공합니다. 10분은 진행 배분이며 실제 외부 에이전트의 생성 속도를 보장하지 않습니다.

첫 요청:

> 이름과 점수를 한 줄에 하나씩 입력하면 높은 점수순으로 정리하는 도구를 만들어줘. 브라우저에서 바로 여는 HTML 파일 하나로 만들고, 한국어로 보여줘. 먼저 입력과 결과가 보이는 간단한 버전을 만들어줘.

수정 요청:

> 같은 점수는 공동 순위로 표시해줘. 1위가 두 명이면 다음은 3위야. 점수가 비었거나 숫자가 아니거나 0~100 범위를 벗어나면 해당 줄을 알려줘. 80점 이상을 강조하고, 이름과 점수가 먼저 보이게 화면을 정리해줘. 정상·동점·누락 입력을 다시 확인해줘.

## 학습 메시지

- 시작 문턱은 낮아졌지만, 지식과 안목이 결과 수준을 좌우합니다.
- 프론트엔드·백엔드의 구조를 알아야 필요한 기능과 처리 위치를 질문할 수 있습니다.
- GUI의 정보 순서·가독성·조작 흐름을 볼 줄 알아야 구체적인 개선을 이끌 수 있습니다.
- 실행 성공은 확인한 조건에서의 성공입니다. 업무 기준에 맞는 결과인지 따로 판단해야 합니다.

## 설명과 실제 연결 범위

어려운 용어는 호버, 키보드 포커스, 클릭에서 정의·쉬운 설명·사례를 제공합니다. PDF에는 용어 설명을 부록으로 포함합니다. 발표 중 모든 설명을 읽을 필요는 없습니다.

P-GPT 구간은 개념 설명과 규칙 기반 재현입니다. 실제 신청 경로, 사용 권한, 호출 주소·형식, 인증 정책은 사내 안내를 확인해 보충해야 합니다. 실제 서비스 연결이나 호출 성공으로 설명하지 않습니다.

## 생성 자산

새 삽화 4종은 제공된 `image_gen` 도구로 생성했습니다. 사용자가 해당 도구를 gpt-image-2.5로 지칭했습니다. 도구의 반환값에는 모델 식별자가 포함되지 않습니다. 원본 PNG와 투명 WebP, 실제 프롬프트는 `assets/`와 `assets/generation.json`에 보관했습니다. 삽화의 정확한 관계·정의·수치는 별도 HTML 텍스트로 제공합니다.

5페이지는 상단의 중복 요청문과 하단 안내·연결 문장을 제거해 시연 창 높이를 331px에서 477px로 확장했습니다. 가상 시연의 범위와 조작 설명은 위 진행안에 유지합니다.
