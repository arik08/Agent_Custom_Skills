## 교육 방향

이 시간에 모든 용어와 명령어를 외울 필요는 없다. “이런 것이 있고, 이럴 때 쓰는구나”라는 감각을 익히는 것이 목적이다. 모르는 것은 AI에게 물어보고, 필요한 작업은 일단 요청한 뒤 결과를 확인하고 수정하면 된다.

도입에서는 세 가지만 전달한다.

1. **업무를 잘 아는 사람이 개발에 참여할 수 있는 환경이 열렸다.** AI에게 무엇을 만들지, 어떤 결과가 맞는지 알려주는 도메인 지식이 중요하다.
2. **코딩 에이전트는 설명을 넘어 실제 작업을 수행한다.** 연결된 도구와 허용된 권한 안에서 파일을 찾고, 코드를 수정하고, 명령어를 실행한다.
3. **사람의 역할은 요구와 판단에 있다.** 원하는 동작을 설명하고, 결과가 업무에 맞는지 확인하고, 필요한 수정을 이어간다.

## 1. Vibe Coding은 무엇이고, 왜 필요한가? — 8분

### 업무를 아는 사람이 만드는 프로그램

- 기존에는 업무 담당자가 요구사항을 전달하고 전문 개발자가 구현하는 경우가 많았다. 이제는 업무 담당자도 AI와 대화하며 직접 시제품을 만들고 개선 과정에 참여할 수 있다.
- 범용 AI는 우리 회사의 업무 규칙, 예외 상황, 좋은 결과의 기준을 처음부터 알지 못한다. 이를 설명하고 결과를 판단하는 사람이 필요하다.
- 코드 작성 지원에서 파일 수정과 실행까지 맡기는 방식으로 작업 범위가 넓어지고 있다. 다만 프로그램이 실행된다는 것과 업무에 맞게 동작한다는 것은 별도로 확인해야 한다.

### 챗봇과 코딩 에이전트의 차이

- 설명 중심의 챗봇: “이 부분을 이렇게 고치세요”라고 코드와 방법을 알려준다.
- 도구를 사용하는 코딩 에이전트: 프로젝트에서 해당 파일과 위치를 찾아 직접 수정하고, 실행 결과를 확인할 수 있다.
- 핵심은 제품 이름보다 **어떤 도구와 작업 공간에 연결되어 실제로 행동할 수 있는가**이다.

### 짧은 흥미 유발 시연 — 약 2분

- 자동 플레이가 가능한 HTML 테트리스 등 시각적으로 이해하기 쉬운 게임을 보여준다.
- 준비된 게임을 실행하고 “속도를 낮춰줘”, “점수를 더 잘 보이게 해줘”처럼 작은 변경을 요청한다.
- 여기서는 가능성을 보여주고, 실제 제작 과정은 뒤에서 따로 설명한다.

## 2. AI 프로그래밍에 필요한 기초 개념 — 15분

용어를 따로 암기시키지 않고, “업무 요청을 입력하고 정리 결과를 받는 프로그램”을 기준으로 연결해 설명한다.

### 프로그램은 어떻게 구성되는가?

**사용자 ↔ 프론트엔드 ↔ API ↔ 백엔드 ↔ 데이터베이스**

- **프론트엔드(Frontend)**: 사용자가 보고 조작하는 화면. HTML은 구조, CSS는 모양, JavaScript는 화면의 동작을 담당한다.
- **백엔드(Backend)**: 입력을 처리하고 업무 규칙을 실행하는 부분. Python 등으로 구현할 수 있다.
- **API(Application Programming Interface)**: 프로그램끼리 정해진 형식으로 요청과 결과를 주고받는 접점이다. 백엔드는 API를 통해 사내 AI 서비스에도 요청할 수 있다.
- **데이터베이스(DB, Database)**: 데이터를 저장하고 찾아 쓰는 곳이다. 모든 프로그램에 별도 DB가 필요한 것은 아니다.
- 단순한 프로그램은 HTML 파일 하나로도 만들 수 있다. 서버가 필요한 웹 프로그램은 배포된 주소로 접속할 수 있으며, 서버 쪽 변경을 사용자에게 제공하기 쉽다.
- 화면에서는 사용성과 취향을, 처리 로직에서는 업무 규칙과 예외를 사람이 확인한다.

### 코딩 에이전트는 어디에서 작업하는가?

- **프로젝트 폴더**: 코드, 자료, 설정을 함께 관리하는 작업 공간이다.
- **터미널(Terminal)**: 명령어를 입력하고 실행 결과를 보는 창이다. PowerShell이나 Bash 같은 셸(Shell)이 명령어를 해석한다. CLI(Command Line Interface)는 명령어로 도구를 사용하는 방식이다.
- 에이전트는 터미널을 통해 Python이나 개발도구를 실행할 수 있다. 마우스·키보드 조작은 별도 컴퓨터 제어 도구가 연결된 경우에 가능하다.
- **라이브러리·패키지**: 다른 사람이 만들어 둔 기능을 가져다 쓰는 부품이다. **패키지 관리자**는 설치와 버전 관리를 돕는다. Python에는 pip·uv, JavaScript 생태계에는 npm 등이 있다.
- **가상환경**: 프로젝트별 Python 패키지 환경을 분리하는 공간이다.
- **Git / GitHub**: Git은 변경 이력 관리 도구, GitHub는 저장소를 온라인에서 보관하고 협업하는 서비스다.

### AI에게 전달할 정보는 어디에 두는가?

- **마크다운(Markdown, `.md`)**: 제목과 목록 등을 간단한 문법으로 작성하는 문서 형식이다.
- **AGENTS.md**: 이를 지원하는 에이전트에 프로젝트의 작업 규칙을 전달하는 문서다.
- **Skill**: 반복하는 작업의 방법과 참고 자료를 묶은 지침이다.
- **MCP(Model Context Protocol)**: AI 애플리케이션을 외부 도구·데이터와 연결하는 공통 규약이다. 실제 사용 범위는 연결된 서버와 권한에 따라 달라진다.
- **환경변수**: 코드에 직접 적는 대신 실행 환경에서 전달하는 설정값이다. API 키 같은 설정을 분리할 때도 사용한다.

### 모르는 것은 AI에게 물어보면 된다

- “지금 나온 API가 무슨 뜻인지 이 프로그램을 예로 설명해줘.”
- “이 프로그램을 실행하려면 무엇을 설치해야 해? 필요한 작업을 진행해줘.”
- “이 링크의 스킬이 어떤 일을 하는지 확인하고, 이 프로젝트에 사용할 수 있게 설치해줘.”
- 모델은 작업의 난도·응답 속도·비용을 기준으로 선택한다. 추론 노력은 문제를 더 깊게 검토하도록 조정하는 설정이며, 제공되는 단계와 적정값은 모델마다 다르다. 구체적인 모델 비교는 강의 직전 확인한 자료로 짧게 소개한다.

## 3. Vibe Coding을 통한 프로그램 제작 시연 — 15분

### 시연 주제: 업무 요청 정리 도구

긴 업무 요청에서 담당자·할 일·기한을 정리하는 간단한 도구를 예제로 사용한다. 외부 API 없이 작동하는 첫 버전을 만들고, 뒤의 사내 API 설명에서 AI 연결 지점을 짚는다. 첫 버전의 규칙 기반 처리를 AI의 문맥 이해로 설명하지 않는다.

1. **개발화면 소개 — 2분**: VS Code의 파일 탐색기, 편집기, 터미널, 에이전트 패널을 보여준다. 배치는 설정에 따라 달라질 수 있다.
2. **자연어로 제작 요청 — 4분**: “업무 요청을 붙여 넣으면 담당자, 할 일, 기한을 정리해 주는 간단한 도구를 만들어줘.” 에이전트가 파일을 만드는 모습을 보여준다.
3. **실행과 결과 확인 — 3분**: 실행 방법을 에이전트에게 묻고 실제 입력으로 확인한다. Python 처리 코드와 HTML 화면이 맡은 역할을 연결해 설명한다.
4. **수정 요청 — 3분**: “기한이 없으면 ‘확인 필요’로 표시해줘”, “결과를 복사하는 버튼을 추가해줘”처럼 결과를 보고 수정한다. 기한이 있는 입력과 없는 입력을 모두 다시 확인한다.
5. **반복 규칙과 실행 방법 정리 — 3분**: “앞으로 화면은 한국어로 만들고, 수정 후 예제 입력으로 확인하도록 AGENTS.md에 정리해줘.” 다른 컴퓨터에서 실행할 때 필요한 패키지와 명령어도 문서화하도록 요청한다.

전달할 메시지는 **“처음부터 완벽하게 설명할 필요는 없다. 요청하고, 실행 결과를 보고, 수정한다”**이다. 코드를 직접 입력하는 수업이나 정형화된 요청 양식 교육으로 확장하지 않는다.

## 4. 개발도구 소개 및 개발환경 준비 — 9분

- 코딩 에이전트는 앱, 편집기 확장, CLI 형태로 사용할 수 있다. 교육에서는 한 가지 환경을 기준으로 설명하고, 다른 형태는 선택지로 소개한다.
- 원안의 후보인 Codex 앱·VS Code 확장·CLI, Cline, Kilo Code, Claude Code는 강의 전에 회사에서 사용 가능한 도구와 설치 경로를 확인한다.
- **VS Code**: 파일을 보고 편집하는 작업 도구. 시연 환경에서는 에이전트 확장과 Python 확장을 사용한다. 한국어 팩과 색상 테마는 선택 사항이다.
- **Python**: Python 코드를 실행할 때 필요하다.
- **Node.js**: JavaScript를 브라우저 밖에서 실행하는 환경이다. 일부 개발도구와 웹 프로젝트에서 필요하며, 단순 HTML 파일 실행에는 필요하지 않을 수 있다.
- **Git**: 변경 이력을 남기거나 저장소를 내려받는 작업에 사용한다.
- 설치를 모두 함께 진행하기보다, 어떤 도구가 왜 필요한지 설명하고 확인된 설치 링크와 시작 순서를 배포 자료에 넣는다.
- 파일 수정·명령 실행 권한과 승인 설정의 의미를 설명한다. Full Access가 모든 환경에서 필수인 것처럼 안내하지 않고, 선택한 도구와 회사 정책에 맞는 설정을 보여준다.

## 5. 사내 AI 응용 프로그램 제작 시 알아야 할 것 — 8분

### P-GPT API와 API 키

- API를 사용하면 사람이 채팅창에 입력하는 대신 프로그램이 AI에 요청하고 결과를 받아 화면이나 업무 처리에 활용할 수 있다.
- API 키는 서비스 사용 권한을 확인하는 인증 정보다. 유출되면 타인이 권한이나 사용량을 악용할 수 있으므로 코드·공유 문서·브라우저 화면에 넣지 않는다.
- **HTML 화면 → Python 백엔드 → P-GPT API → 처리 결과 → 화면** 순서로 설명하고, 키는 서버 측 설정에서 사용하도록 한다.

### 요청과 응답 예시

- 업무 요청 본문을 보내고 담당자·할 일·기한을 반환받는 흐름을 보여준다.
- Responses API 예시는 P-GPT에서 해당 방식과 기능을 지원하는지 먼저 확인한 뒤 사용한다. 실제 지원 형식이 다르면 그 형식으로 설명한다.
- 웹 검색은 P-GPT 내장 검색과 프로그램의 직접 웹 접근을 구분한다. 내장 검색 지원 여부, 사내 인증서가 필요한 경로, 네트워크 허용 범위는 담당 부서의 안내를 확인한다.
- 신청 위치·승인 절차·사용 가능한 모델·연결 주소는 확인된 사내 자료를 바탕으로 보충한다. 미확인 내용을 실제 연결 성공 사례로 표현하지 않는다.

## 6. Q&A — 5분

- 오늘 나온 개념, 개발환경을 시작하는 방법, 각자의 업무에 적용할 수 있는 범위를 중심으로 질문을 받는다.
- 별도 과제 없이 마무리한다. 발표자료와 실행 안내를 제공하여 이후에도 AI에게 물어보며 다시 따라갈 수 있도록 한다.

## 강의 전 준비 및 진행 기준

- 도입 게임과 후반 제작 시연을 구분해 준비한다. 제작 시연에는 시작 상태·중간 상태·완성 상태를 보관한다.
- 생성이나 설치가 길어지면 준비된 중간 상태로 이어가고, 준비본으로 전환했다는 사실을 밝힌다. Q&A 5분은 확보한다.
- 시연 입력에는 실제 사내 정보 대신 가상 업무 자료를 사용한다. 정상 입력과 누락 정보가 있는 입력으로 결과를 확인한다.
- 설치 링크, 모델 선택 설명, 권한 설정 화면, P-GPT 신청 및 호출 방식은 강의 전에 확인한다. 이 문서는 교육 구성안이며 해당 항목의 최신 동작이나 사내 연결을 검증한 자료는 아니다.
- 후속 제작물: 발표자료, 설치·실행 안내, 시연 예제, 확인된 사내 API 참고자료. 이번 작성 범위는 기획안이다.
