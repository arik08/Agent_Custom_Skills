# AI 코딩 교육 진행 노트

- 60분 구성, 29장 본문 + 3장 부록
- N 키로 현재 장의 노트를 볼 수 있습니다. 투사 화면에도 보이므로 강사용 참고 시 사용하세요.
- 이미지와 글꼴은 HTML에 포함되어 오프라인 열기가 가능합니다. 외부 링크는 인터넷이 필요합니다.

## 1. 내 업무를 아는 사람, AI와 함께 만들다.

시작 1분. 교육 대상은 코딩 입문자. 설치를 동시에 따라 하는 실습이 아니라 개념과 시연 중심임을 알린다. 오늘 외울 것은 문법보다 요청·실행·확인의 흐름이다.

## 2. 외우지 않아도 됩니다. 흐름만 가져가세요.

1분. 모든 개념을 한 번에 이해할 필요가 없다고 안내한다. 결과 확인의 책임은 사람에게 있다는 메시지를 자연스럽게 전달한다.

## 3. 한 시간, 작은 업무 도구 하나

30초. 제작 시연을 중심에 놓았다. 예상 질문이 길어지면 개념 설명을 줄이고 16:55에는 마무리로 이동한다.

## 4. AI에 필요한 것은 여러분이 아는 업무입니다.

2분. 예: 미완료의 의미가 회사마다 다르다. 보류를 포함하는지, 담당자가 빈 행은 어떻게 처리하는지 알려줄 수 있는 사람은 현업 담당자다. AI가 회사 업무를 자동으로 안다고 가정하지 않는다.

## 5. 설명을 받는 데서, 실제 파일을 바꾸는 데로

2분. 중요한 포인트는 코드를 설명해 주는 데 그치지 않고 해당 파일의 필요한 부분을 찾아 고치는 것. 컴퓨터 전체나 마우스를 항상 제어할 수 있는 것은 아니다. GUI 제어는 별도 지원 도구와 권한이 필요하다.

## 6. “완료된 업무는 숨겨줘.”

소개 챕터 종료까지 총 8분. 실제 Agent에 output/demo 폴더를 열고 “화면에 완료 항목을 숨기는 버튼을 추가하고 동작을 확인해줘”라고 요청한다. 라이브가 지연되면 이 완성 예시와 본 시연의 내장 데모를 사용한다. 이 화면 자체는 설명용 예시임을 말한다.

## 7. 프로그램은 역할을 나눠 일합니다.

2분. 화면은 주문 창구, API는 주문 형식, 백엔드는 처리 담당, DB는 보관소에 비유한다. Python은 백엔드의 한 선택지다. 정적 HTML 예제는 브라우저만으로 실행할 수 있음을 연결한다.

## 8. 화면의 구조·모양·동작은 서로 다른 역할입니다.

2분. Frontend는 취향뿐 아니라 사용성, 접근성, 화면 크기, 동작 검증도 중요하다. Backend 역시 보안과 예외 처리가 중요하여 AI가 무조건 정확하다고 말하지 않는다.

## 9. 라이브러리는 도구, 가상환경은 프로젝트별 공구함

1분 30초. 라이브러리는 미리 만들어진 기능을 재사용하는 것. 가상환경은 Python 패키지와 버전 충돌을 줄인다. 운영체제 전체를 격리하는 보안 장치는 아니다. 오늘 예제는 Python 기본 라이브러리만 사용한다.

## 10. 터미널은 컴퓨터에게 글로 지시하는 창입니다.

1분 30초. CLI는 명령줄 인터페이스. CMD, PowerShell, Bash는 서로 다른 셸이며 명령이 다를 수 있다. Agent는 터미널을 통해 파일·프로그램을 다룬다. ipconfig는 네트워크 정보를 표시하므로 개인 화면 정보를 불필요하게 공유하지 않는다.

## 11. 변경 이력과 실행 설정도 프로젝트의 일부입니다.

1분 30초. 저장 버튼과 Git 커밋은 다르다. GitHub에 올릴지는 회사 정책과 자료 성격에 따라 정한다. 환경변수의 실제 값은 화면에 보여주지 말고 이름만 설명한다.

## 12. 모델은 작업에 맞게, 추론 노력은 필요한 만큼

2분 30초. 원안의 Sol/Terra/Luna 비교를 유지한다. 현재 공식 목록에는 Astra도 있으므로 이 세 가지가 전체 모델 목록인 것처럼 설명하지 않는다. 제공 목록은 로그인·관리자 설정에 따라 다름. Artificial Analysis는 추가 비교 참고이며 점수만으로 업무 적합성을 판단하지 않는다.

## 13. 오늘 만들 것: 업무 요청 요약기

1분. 예제 데이터는 가상 데이터다. 업무상 개인정보나 회사 자료를 넣지 않는다. output/demo/summarize.py와 tasks.csv, report.html이 백업으로 제공된다. HTML 데모는 외부 API를 호출하지 않는다.

## 14. 좋은 요청에는 입력·처리·출력·기준이 있습니다.

2분. 네 줄을 한 줄씩 노출하며 읽는다. 프롬프트 문구를 외우는 대신 결과를 판단할 조건을 넣는다는 원칙을 강조한다. AI에게 먼저 계획을 설명해 달라고 해도 된다.

## 15. 개발 화면은 네 영역만 보세요.

1분. 실제 VS Code 화면으로 전환해서 같은 네 영역을 짚는다. 여기의 그림은 실제 제품 스크린샷이 아닌 교육용 배치도다.

## 16. Python이 자료를 정리하고, HTML이 결과를 보여줍니다.

3분. Agent에 프롬프트를 전달하고 코드 생성과 실행을 지켜본다. Python 실행 후 생성된 report.html을 연다. 라이브 생성이 지연되면 제공된 완성본을 실행한다. 소스 코드 줄마다 설명하지 말고 입력→출력 관계를 보여준다.

## 17. 완성 다음에는, 사용해 보며 고칩니다.

3분. 미완료 버튼을 누르면 4건. 민지를 선택하면 2건, 준호는 1건. 초기화하면 6건. 필터를 여러 순서로 조작해 결과가 유지되는지 확인한다. 이 데모는 작성된 HTML/JavaScript가 실행되는 예제로, 지금 AI가 코드를 생성하는 장면은 아니다.

## 18. 오류는 다음 요청의 재료입니다.

3분. 제공된 예제의 CSV 복사본에서 상태 열 이름을 바꿔 실행하고 명확한 오류를 보여준다. 오류를 숨기는 대신 원인을 이해하고 같은 종류의 입력에도 적용되게 고친다. 정상 입력으로 다시 실행하여 기존 동작이 유지되는지도 확인한다.

## 19. 반복되는 약속은 AGENTS.md에 남깁니다.

4분. 직접 문법을 외워 작성할 필요 없이 Agent에게 정리하도록 요청한다. 실제 파일을 열어 원하지 않는 규칙이 들어갔는지 검토한다. 파일이 존재한다고 모든 지침이 반드시 지켜진다는 보장은 없다. 새 세션에서 어떤 지침을 읽었는지 확인하도록 요청해 볼 수 있다.

## 20. 도구는 하나의 경로로 시작하세요.

2분. Cline, Kilo Code 같은 대안도 있지만 입문자는 여러 도구를 동시에 설치할 필요 없다. 회사의 앱 금지 정책은 제공 원안에 따른 맥락이며 현재 정책을 독립 검증한 것은 아니다. CLI가 회사 제한을 우회하는 방법인 것처럼 설명하지 않는다.

## 21. 설치할 것과, 필요할 때 추가할 것을 나눕니다.

3분. HTML만 실행한다면 Python이 필요 없지만 이 강의의 CSV 예제에는 필요하다. Codex CLI의 npm 설치는 Node.js가 필요하고 독립 설치 경로는 별도다. 설치 후 버전 확인과 프로젝트 폴더 열기까지 보여준다.

## 22. 권한은 “어디까지 맡길지”의 설정

4분. 원안의 “자꾸 안 물어보도록 Full Access”는 승인 횟수만으로 설명하지 않고 접근 범위와 승인 정책을 구분해 정리했다. 현재 CLI에서는 /permissions로 확인할 수 있다. 회사 관리 정책은 개인 설정으로 우회하지 않는다. 실제 업무 원본에 대한 광범위한 변경 권한을 교육 중 켜지 않는다.

## 23. AI로 만드는 것과, 프로그램이 AI를 쓰는 것은 다릅니다.

1분 30초. 이 구분이 이번 챕터의 핵심. Coding Agent 로그인과 P-GPT API 인증은 별개일 수 있다. 정해진 규칙으로 셀 수 있는 건수 집계에는 LLM을 반드시 쓰지 않는다.

## 24. API는 연결 약속, API Key는 인증 정보

1분 30초. 열쇠 비유는 인증의 역할을 설명하기 위한 것이다. 키와 인증서는 서로 다르다. 브라우저에 키를 넣으면 소스와 네트워크 요청에서 노출될 수 있음을 설명한다.

## 25. P-GPT를 연결하기 전에 네 가지를 확인합니다.

2분. 강의 전에 사내 공식 안내를 확보하여 이 슬라이드와 발표자 노트에 링크 및 담당자를 채운다. 현재는 준비 항목을 설명하는 장이며 실제 신청 절차를 검증한 자료는 아니다.

## 26. Responses API는 입력을 보내고 결과를 받습니다.

1분 30초. 이 코드는 API 호출 구조를 설명하는 예제이며 실행 검증하지 않았다. 실제 키를 넣지 말고 실행도 선택 사항. P-GPT가 OpenAI와 호환된다고 단정하지 않는다. 주소·헤더·인증·모델·SDK 호환 여부를 사내 문서로 확인한 뒤 적용한다.

## 27. 연결 오류는 인증과 통신을 나눠 살펴봅니다.

1분 30초. 사내 인증서 경로, 구체 환경변수 이름은 런타임과 게이트웨이 정책에 따라 다르므로 임의로 정하지 않았다. 오류 메시지에서 키를 가린 뒤 원인별로 분류한다. 사내 연동의 실제 호출 성공은 별도 검증이 필요하다.

## 28. 첫 과제는, 매주 반복하는 작은 일 하나

2분. 예시: 파일명 정리, 표에서 조건에 맞는 행 추출, 텍스트를 읽기 쉬운 보고서로 변환. 실제 민감 자료보다 가상 샘플로 시작한다. 모르겠으면 AI에게 쉬운 설명과 작은 예제를 요청하도록 안내한다.

## 29. 어떤 반복 업무를 가장 먼저 바꾸고 싶으세요?

3분 질의응답. 완성된 프로그램을 업무에 적용할 때는 데이터와 운영 환경에 맞는 확인이 추가로 필요하다고 답한다. 상세 설치 질문은 부록을 이용한다.

## 30. 공식 안내에서 시작하세요.

참고용 부록. 발표 60분에는 포함하지 않는다. Python/VS Code/Node.js/Git은 공식 다운로드 페이지로 연결. 모델 비교 사이트는 평가 조건을 읽고 참고한다.

## 31. CLI도 프로젝트 폴더에서 시작합니다.

참고용 부록. npm 명령은 PowerShell, 슬래시 명령은 Codex 대화창에 입력한다. 회사 로그인·망 정책은 별도다. 설치를 실제로 실행한 것은 아니다.

## 32. 모르는 순간에도 이렇게 요청할 수 있습니다.

공식 기술 출처와 재사용할 요청 문장을 모았다. 그림은 이 강의를 위해 AI로 생성한 개념 삽화이고, 도해와 화면 배치도는 교육용으로 제작했다. P-GPT 사내 절차·실제 호출은 미검증 상태다.
