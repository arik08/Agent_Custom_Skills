# P-Harness 교육자료 상세 기획안

작성일: 2026-09-28  
상태: 콘텐츠·화면·상호작용 설계. HTML 구현 및 실제 제품 검증 전.

## 1. 제작 방향

**제목: P-Harness — 질문에서 업무 보고서까지**  
부제: 자료를 연결하고, 일을 맡기고, 결과를 검증하는 사용자 가이드

사무직 사용자가 처음에는 순서대로 따라 배우고 교육 후에는 필요한 기능만 찾아보는 세로형 HTML 매뉴얼을 제작한다. 기능 나열보다 업무 한 건이 완성되는 과정을 중심에 둔다. 상사의 피드백을 필수 내용의 기준으로 삼고 기존 HTML의 조작 설명을 참고 영역까지 보존한다.

최종 배포 파일은 `p-harness-guide.html` 한 개다. 가로형·슬라이드형·별도 발표 버전은 제공하지 않는다. 전체화면은 동일 문서의 표시 상태이며 콘텐츠를 복제하지 않는다. 기획서와 검증 자료는 제작 관리 자료이지 별도 교육 버전이 아니다.

### 학습 완료 기준
- 자신의 업무 목적·대상·기간·자료·산출물 조건을 포함해 요청문을 작성할 수 있다.
- 모델, Skill, MCP의 역할 차이를 설명하고 업무에 맞게 선택할 수 있다.
- 제공한 문서의 핵심 표·그림이 제대로 인식되었는지 확인할 수 있다.
- 보고서의 수치·기준일·출처·추정 여부를 검토하고 구체적으로 수정을 요청할 수 있다.
- 필요한 사용법을 목차 또는 검색으로 다시 찾을 수 있다.

## 3. 장별 상세 콘텐츠

### 00. 이 가이드 시작하기
- 첫 화면에 제목, 한 문장 소개, `처음부터 보기`, `업무별 요청문 찾기`를 배치한다.
- 표지 아래에 교육용 경쟁사 보고서 일부를 보여준다. 결과물의 구성과 근거 확인 위치를 설명한다.
- 핵심 안내: “자료 조사와 초안 작성에 활용하고, 최종 판단은 업무 담당자가 확인합니다.”
- 시작 화면을 과도하게 높이지 않아 목차와 실제 내용이 바로 보이게 한다.

### 01. P-Harness 이해하기
- LLM은 이해·추론·작성, Skill은 업무 절차·판단 기준, MCP는 연결된 도구·데이터 접근을 맡는다고 설명한다. MCP를 검색 데이터 전용 개념으로 한정하지 않는다.
- Harness는 이 요소와 대화·파일·실행 과정을 묶는 환경으로 설명한다.
- 같은 경쟁사 분석 요청을 기준으로 각 구성요소의 역할을 단계별로 보여준다. 실제 내부 호출 순서를 검증한 것처럼 표시하지 않는다.
- 현재 강점, 향후 고도화 방향, 담당자 판단의 필요성을 구분한다.
- MyHarness와의 비교는 상세 펼침 영역으로 둔다. 운영 구조와 출시일은 배포 시점에 확인한다.
- feedback.md의 영상은 선택 참고 링크로 제공한다. 영상 내용은 별도 확인 후 요약하며 자동 재생하지 않는다.

### 02. 첫 업무 시작하기
- 실제 화면 전체 캡처에 ① 대화 목록 ② 채팅 ③ 입력창 ④ 모델 설정 ⑤ 결과물 영역을 표시한다. 번호와 위치는 실제 캡처 기준으로 확정한다.
- 따라 하기: 자료 첨부 → 업무 목적 입력 → 추가 질문에 답변 → 진행 상태 확인 → 결과물 열기.
- 각 단계는 동작, 예상되는 화면 변화, 확인할 점을 함께 적는다.
- 좌상단 `/` 명령어 창으로 도구 목록을 먼저 안내하고 `@`, `$`, 드래그 첨부를 보조 경로로 구분한다. 이름만 입력한 것과 실제 파일 선택의 차이를 보여준다.

### 03. 모델과 Effort 선택
- 단순 정리·초안, 일반 조사·분석, 복잡한 판단으로 나누어 선택 기준을 안내한다.
- feedback.md에 적힌 GPT-5.6-Luna·Gemini-3.8-Flash의 간단한 업무 활용, GPT-5.6-Terra 또는 GPT-5.6-Sol의 Medium 수준의 일반 업무 활용을 초안 기준으로 삼는다. 실제 명칭과 허용 Effort는 운영 화면 확인 후 확정한다.
- Effort는 작업 난이도·시간·사용량을 함께 고려하도록 설명한다. 결과물 형식만으로 난이도를 고정하지 않는다.
- 월별 사용량 확인 위치와 불필요한 재작업을 줄이는 방법을 소개한다.
- 원본의 GPT-5.6-Astra·GPT-5.6-Sol·GPT-5.6-Terra·GPT-5.6-Luna, Gemini-3.8-Flash와 GPT-6-Astra·GPT-6-Sol·GPT-6-Luna를 누락 없이 소개한다. GPT-6의 P-GPT 미적용 표시는 원본 작성 당시의 구분으로 설명한다.
- 출력단가·상대비용은 원본 자료의 비교값으로만 제시한다. 현재 요금이나 총 사용 비용으로 단정하지 않으며, 캐시 할인·모델 전환 비용 배수를 일반 규칙으로 사용하지 않는다.
- 가격 그래프보다 “이 업무에서 무엇을 고를까” 비교표를 우선한다.

### 04. Skill 활용하기
- 우선 경로는 좌상단 `/` 명령어 → 스킬 펼치기 → 이름·설명·활성 상태 확인이다. 실제 FHD 화면으로 버튼과 펼침 목록을 안내한다. `$`와 입력창 호출 버튼은 특정 도구를 요청에 넣는 보조 방법으로 설명한다.
- 일반 교육의 우선순위는 등록된 Skill 찾기 → 설명 읽기 → 적용 → 결과 확인이다.
- 그룹별 목록은 이름 / 담당 업무 / 필요한 입력 / 예상 산출물 / 확인일로 정리한다.
- 제공 자료에는 확정된 그룹별 Skill 명단이 충분하지 않으므로 실목록 확보 전 이름을 만들어 채우지 않는다.
- 제작·개선은 심화 펼침 영역에 배치한다. 자료·절차·판단 기준·금지사항·결과 형식 → 샘플 테스트 → 피드백 → 재검증 흐름을 설명한다.
- 같은 예시만 통과시키지 않고 다른 입력, 자료 누락, 모호한 요청도 확인하도록 안내한다.

### 05. MCP 활용하기
- 우선 경로는 좌상단 `/` 명령어 → MCP 펼치기 → 이름·설명·연결 기관 확인이다. 목록의 활성 표시와 실제 조회 성공을 구분한다.
- 기본 구조: 업무 목적 → 라우팅 분류 → 연결 기관 → 얻을 수 있는 정보 → 확인할 점.
- 기업 공시: company-disclosure 등 / 경제·금융: ecos, kosis, worldbank, macro-finance 등 / 무역·에너지·산업: comtrade, trade-market, eia 등 / 법령·국회·규제: korean-law, national-assembly, legislation-regulation 등 / 기술·연구: patent-tech 등으로 제공 자료를 재구성한다.
- 명칭과 기관 연결은 기존 HTML에 기재된 목록이며 현재 탑재 여부를 재확인한다. development-finance 등 불명확한 기관 표기도 확인 대상으로 남긴다.
- 내부 연결은 현재 사용 가능·예정·확인 필요를 구분한다. 실제 제품에서 확인하지 않은 연결을 사용 가능한 것으로 표현하지 않는다.
- 조회 성공과 데이터 적합성은 구분한다. 기준일·단위·국가 및 품목 코드·기업 식별자·원문을 확인한다.
- 연결 실패, 결과 없음, 오래된 데이터는 다른 상태로 설명한다. 미조회 상태를 “해당 자료 없음”으로 단정하지 않는다.

### 06. 일을 잘 맡기는 요청법
- 요청의 여섯 요소: 목적·독자 / 대상·범위 / 기준 시점 / 제공 자료 / 수행할 분석 / 결과 형식·검증 조건.
- “포스코 주요 경쟁사 분석해줘”에 조건을 차례로 더하는 교육용 비교 화면을 만든다.
- 조건 추가는 사용자가 버튼으로 진행하며 완성 요청문은 항상 복사할 수 있다.
- 핵심 문구: “작업에 필요한 정보가 부족하면 먼저 나에게 질문하고, 확인된 범위에서 진행해줘.”
- 긴 요청이 무조건 좋은 것이 아니라 필요한 조건이 분명한 요청이 좋다는 점을 설명한다.
- 수정 예시는 “더 멋지게”보다 “요약을 앞에 배치하고, 확인되지 않은 원인은 가설로 표시해줘”처럼 구체화한다.

### 07. 사내자료 활용하기
- ECM에서 내려받은 기존 최종산출물과 이번 작업 자료를 함께 제공하는 흐름을 설명한다.
- 제공 자료 기준의 DRM 첨부 안내는 실제 지원 파일과 권한 조건을 확인한 뒤 게시한다. ECM 직접 연결과 다운로드 후 첨부를 혼동시키지 않는다.
- 첨부 후 “중요한 표의 항목·단위·기간을 먼저 설명해줘”라고 요청하는 예시를 제공한다.
- 복잡한 그림은 필요한 영역을 캡처해 추가하고, 원문 페이지·표 번호와 함께 연결한다.
- 읽지 못한 부분을 추정으로 채우지 말고 명시하도록 요청한다.
- 기존 보고서는 형식·판단 기준의 참고 자료이며 과거 수치를 현재 사실로 재사용하지 않도록 설명한다.

### 08. 경쟁사 분석 따라 하기 — 중심 사례
1. 업무 정의: 포스코와 주요 철강사의 2023~2025년 실적 비교라는 제공 예시를 교육용으로 사용한다.
2. 자료 확인: 연결·별도, 회계연도, 통화, 사업 범위, 수치 단위를 확인한다.
3. 추가 질문: 비교 기준과 보고 대상, 분량, 제공 자료의 우선순위를 확정한다.
4. 조사: 기업 공시 등 근거의 기준 시점과 출처를 확인한다. 특정 MCP가 항상 자동 호출된다고 약속하지 않는다.
5. 보고서: 핵심 결론 → 비교표 → 차이의 원인·가설 → 원료 수급 구조 → 제품·판매 전략 → 시사점 → 출처.
6. 검증: 사실과 추정 구분, 원문 대조, 비교 기준 통일, 부족한 근거 표시.
7. 수정: 사용자가 지적한 문제를 반영하고 변경된 내용을 재확인한다.

실제 조사 결과가 없는 단계에서는 숫자를 창작하지 않는다. 화면 예시는 `교육용 예시`로 표시하고 수치가 필요하면 가상 데이터임을 표·차트 인접 위치에 명시한다. 이 교육자료 제작은 경쟁사 실적 조사를 별도로 수행하는 과제로 확장하지 않는다.

### 09. 업무별 요청문
- 경쟁사 실적 분석: 기업·기간·비교 기준·원료 수급·마케팅·보고 대상 포함.
- 경영환경 전망: 성장·환율·원료·에너지·전후방 산업·규제 등 검토 범위와 시나리오 구분. 상사 예시의 자동차·조선·건설·에너지·데이터센터·전기강판을 반영한다.
- 입법동향: 국가·기준일·법안 상태·관련 사업·예상 영향·대응·발의자 정보를 포함하되 확인되지 않은 정보는 미확인으로 남긴다. 계류 법안과 확정 법률을 구분한다.
- 세 사례 모두 부족한 요청 / 개선한 요청 / 추가 질문 예 / 결과 확인 항목을 같은 형식으로 제공한다.
- 과거 기준일은 교육용 예시임을 명시하고 실제 사용 전 바꿀 자리를 표시한다.
- 복사 템플릿은 `[회사]`, `[기간]`, `[보고 대상]` 같은 치환 항목을 사용한다. 미작성 치환 항목이 남았음을 안내한다.

### 10. 결과물과 대화 관리
- 원하는 형식 지정 → 결과 열기 → 내용 검토 → 수정 → 다운로드를 설명한다.
- HTML 기본 생성, 지원 파일 형식, Viewer 편집·공유·다운로드 기능은 실제 운영 확인 후 반영한다.
- 작은 문구 수정과 표·차트·구조 수정의 차이를 사례로 안내한다.
- 대화 검색·이름 변경·고정·좋아요·분기·파일 관리는 기능별 짧은 설명으로 제공한다.
- 삭제의 서버 보관 방식 등 사용자에게 필요한 범위를 넘는 내부 구현 주장은 검증 없이 넣지 않는다.
- 단축키 표는 대기 중과 실행 중 동작을 구분한다. Enter, Shift+Enter, Ctrl+Enter 등의 정확한 동작을 실제 화면에서 확인한다.
- ECharts·Mermaid 등 구현 도구 이름은 일반 사용자에게 요구하지 않는다. “추세를 차트로”, “절차를 흐름도로” 같은 요청을 본문에 사용한다.

### 11. 검증과 문제 해결
- 완료 체크: 목적 충족 / 기간·단위 / 원문 수치 / 비교 기준 / 출처 / 추정 구분 / 누락 / 담당자 판단.
- 문제 해결 표: 증상 → 먼저 확인할 사항 → 추가 요청 예 → 해결되지 않을 때 조치.
- 필수 증상: 파일을 못 읽음, 표 일부 누락, 출처 부족, 조회 실패, 다른 기업 데이터, 요청 범위 누락, 결과물 잘림.
- “항상 다시 실행” 대신 읽을 수 있는 자료 제공, 범위 축소, 기준 수정 등 원인별 대응을 설명한다.

### 12. 빠른 참고
- 용어, 단축키, 요청문으로 직접 이동하는 색인을 제공한다.
- 페이지 하단에 매뉴얼 수정일과 제품 기능 확인일을 별도로 표시한다.
- 제공 자료와 외부 링크를 구분한다. 검증되지 않은 제품 정보에는 내부 편집 과정에서 확인 표시를 남기되 최종 배포본에는 확인된 문장 또는 명확한 한계 설명을 사용한다.

## 4. 화면·시각 디자인

- 데스크톱: 상단 도구 영역 + 왼쪽 목차 약 260~280px + 오른쪽 세로 본문.
- 본문은 약 960~1120px 이내로 제한하고 일반 문단은 더 짧은 읽기 폭을 사용한다. 표·이미지는 본문 폭을 활용한다.
- 기본 본문 18px, 표 15~16px, 캡션 14px, 장 제목 28~36px를 권장한다. 좁은 화면에서도 본문 16px 이상을 유지한다.
- 흰색 바탕, 남색 제목, 포스코 블루(#05507D) 강조와 연한 블루 배경을 기본으로 한다. 녹색·청록색 강조는 사용하지 않는다. 주의는 따뜻한 주황 계열, 오류는 붉은 계열로 제한한다.
- 도입부·업무 흐름·표·실제 화면을 서로 다른 구성으로 배치해 동일한 카드의 반복을 피한다.
- 모서리 반경은 4~8px 수준으로 절제하고 장식보다 정보 구분에 사용한다.
- 기본 장 구성은 핵심 메시지 → 시각 자료 → 따라 하기 → 확인할 점이다. 화면마다 모든 요소를 억지로 반복하지 않는다.
- 좁은 화면은 같은 HTML에서 목차를 서랍으로 전환한다. 가로형 버전을 생성하지 않는다.
- 긴 표는 해당 표 영역에서만 가로 스크롤하고 페이지 전체의 가로 넘침은 허용하지 않는다.
- 애니메이션은 선택한 단계의 강조 정도로 제한한다. 자동 스크롤 강제 이동과 휠 가로채기는 사용하지 않는다.

## 5. 상호작용 명세

### 5.1 목차
- 장과 세부 항목을 모두 제공한다. 상위 장은 접을 수 있지만 현재 장은 자동으로 드러난다.
- 클릭 시 지연 애니메이션 없이 대상 제목으로 이동하고 고정 헤더 높이만큼 여유를 둔다.
- 대상이 접힌 영역이면 먼저 펼친다. 이미지 로딩 후에도 제목 위치가 크게 바뀌지 않도록 이미지 크기를 예약한다.
- 현재 읽는 항목을 색과 표시선으로 강조하고 접근성 상태도 제공한다.
- 목차 자체는 독립 스크롤한다. 본문을 읽는 동안 목차 전체가 튀지 않도록 필요한 경우에만 현재 항목을 노출한다.
- 클릭 이동은 주소 해시에 반영하고 뒤로 가기로 돌아갈 수 있게 한다. 단순 스크롤은 탐색 기록을 쌓지 않는다.
- 파일 첨부 배포에서는 해시가 같은 로컬 파일 안에서의 위치를 뜻한다. 다른 PC에서 공유 가능한 URL은 동일 문서가 접근 가능한 위치에 있을 때만 제공한다.

### 5.2 검색
- 제목, 본문, 이미지 캡션, 요청문, 용어를 검색한다. 이미지 픽셀 속 글자 자체를 OCR 검색하는 기능은 포함하지 않는다.
- 결과에는 장 제목과 주변 문장을 제공하고 선택하면 필요한 펼침 영역을 열어 해당 위치로 이동한다.
- 입력의 앞뒤 공백과 영문 대소문자 차이를 정규화한다. 한글 조합 입력 중 검색 갱신이 방해되지 않게 한다.
- 검색 결과 0건 상태와 검색 초기화를 제공한다. 사용자 입력을 HTML로 해석하지 않는다.
- 검색이 본문 전체를 숨기는 방식은 피하고 검색 결과 목록을 따로 제공한다.

### 5.3 전체화면과 우클릭
- HTML 문서가 받는 우클릭 이벤트에서 기본 메뉴를 대신해 전체화면 진입·해제를 실행한다. 이미지 확대 창과 검색 영역에서도 같은 규칙을 적용한다.
- 상단 버튼을 누르는 경우에도 동일 동작을 사용한다. 키보드 사용자는 버튼으로 진입할 수 있다.
- Esc 종료는 브라우저 기본 전체화면 동작을 존중하고 실제 `fullscreenchange` 상태를 기준으로 버튼 표시를 갱신한다.
- Shift+우클릭은 브라우저 기본 메뉴용 예외로 제공하고 지원 브라우저에서 확인한다. 안내는 짧은 도움말로 제공한다.
- 전체화면에서도 세로 본문, 검색, 목차, 읽던 위치를 유지한다. 목차 숨김은 별도의 선택이다.
- Fullscreen API 권한 거부·미지원이면 상태를 거짓으로 바꾸지 않는다. “이 환경에서는 전체화면 전환이 제한됩니다. 문서를 브라우저에서 직접 열어주세요.”처럼 해결 방법을 안내한다.
- 브라우저 도구 모음, 브라우저 자체 메뉴, 외부 영상 iframe 내부는 문서에서 제어할 수 없다. 따라서 참조 영상은 외부 링크를 기본으로 하여 문서 내부 우클릭 범위를 일관되게 유지한다.
- 이미지 확대 중 Esc는 브라우저가 전체화면 종료에 먼저 사용할 수 있다. 제품 검증 시 실제 동작을 기록하고 확대 창에는 항상 명시적 닫기 버튼을 둔다.

### 5.4 이미지 확대
- 캡처 클릭 또는 확대 버튼으로 연다. 이미지 설명, 확대·축소, 화면에 맞춤, 닫기를 제공한다.
- 키보드 초점은 확대 창 안에서 이동하며 닫으면 원래 버튼으로 돌아간다.
- 이미지는 화면에 맞게 시작하고 세부 글자는 확대하여 읽을 수 있게 한다. 확대 창 안에서 이동할 수 있다.
- 핵심 조작 안내는 이미지 외 본문에도 제공한다. 이미지가 손상되어도 문맥을 이해할 수 있어야 한다.

### 5.5 요청문 복사·상세 펼침
- 복사 버튼은 해설을 제외한 요청문만 복사한다. 성공 안내는 실제 클립보드 기록 성공 후에만 표시한다.
- 로컬 파일 또는 브라우저 정책으로 복사가 실패하면 선택 가능한 원문과 수동 복사 안내를 제공한다.
- 심화·부가 설명만 접는다. 핵심 학습 내용과 필수 주의사항을 모두 접어 숨기지 않는다.
- 요청문 복사는 교육용 HTML의 기능이며 P-Harness로 자동 전송하지 않는다.

## 6. 이미지 제작·확보 계획

| 구분 | 계획 이미지 | 확보 또는 제작 방식 |
|---|---|---|
| 실제 UI | 전체 화면과 영역 번호 | 운영 버전 캡처 필요 |
| 실제 UI | 모델·Effort 선택 | 실제 메뉴 캡처 필요 |
| 실제 UI | 문서 첨부와 첨부 완료 | 지원 파일로 확인 후 캡처 |
| 실제 UI | Skill·MCP 선택 | 실제 탑재 목록 기준 캡처 |
| 실제 UI | 결과물 열기·다운로드 | 실제 산출물로 캡처 |
| 개념도 | 모델·Skill·MCP 협력 구조 | HTML/SVG로 제작 |
| 개념도 | ECM 자료 활용 흐름 | HTML/SVG로 제작 |
| 교육 예시 | 요청 구체화 전후 | 선택 가능한 실제 텍스트로 제작 |
| 교육 예시 | 표·그림 인식 확인 | 공개 또는 비식별 샘플로 제작 |
| 결과물 예시 | 보고서 구성·근거 확인 | 교육용 예시임을 명시 |

초기 기준은 실제 화면 5종 이상과 설명용 시각 자료 3종 이상이다. 수량 자체보다 각 조작을 이해할 수 있는지를 완료 기준으로 삼는다. 실제 자료 확보에 따라 필요한 세부 캡처를 추가한다.

화면 캡처에 개인 이름·사내 식별 정보·민감 문서 내용이 드러나면 교육에 필요한 부분만 사용한다. AI로 생성한 가짜 제품 화면은 실제 조작 안내에 사용하지 않는다. 추상적 AI 장식 이미지는 필수가 아니다.

배포 HTML에는 이미지 데이터를 포함한다. 원본 고해상도 캡처는 input에 보존하고 주석·크기 조정 등 가공본은 output 하위에서 관리한다. 같은 캡처를 여러 해상도로 무분별하게 중복 삽입하지 않으며 텍스트 가독성을 기준으로 용량을 조정한다.

## 9. 유지보수와 배포 원칙

- 최종 사용자 배포본은 하나의 세로형 HTML이다.
- 본문 제목을 기준으로 목차와 검색 대상을 구성한다. 독립된 목차 문구를 수작업으로 이중 관리하지 않는다.
- 모델 안내, Skill 목록, MCP 목록처럼 변하는 정보는 한 곳에서 관리하고 다른 장은 그 위치로 연결한다.
- CSS·JavaScript·핵심 이미지는 파일 안에 포함한다. 외부 CDN·외부 폰트 없이도 핵심 기능이 작동하도록 한다.
- 영상과 원문 링크는 선택 참고 자료이며 네트워크가 끊겨도 본문 열람은 가능해야 한다.
- 인쇄 CSS가 필요하면 같은 문서에서 제공하되 별도의 PDF 교육본 제작·동기화는 현재 범위에 포함하지 않는다.
- 요구사항은 input/requirements.md에, 생성물과 검증 자료는 output에 저장한다. 참고자료 원본은 덮어쓰지 않는다.

## 10. 제작 순서

1. 본 기획안 기준으로 실제 교육 원고를 작성하고 사실 확인 대상 문장을 구분한다.
2. 운영 화면·모델·Skill·MCP 목록과 지원 동작을 확인한다.
3. 필요한 캡처를 확보하고 개념도·교육 예시를 제작한다.
4. 단일 HTML에 본문, 목차, 검색, 확대, 전체화면, 복사를 구현한다.
5. 실제 브라우저에서 읽기·탐색·예외 경로와 화면 크기별 레이아웃을 확인한다.
6. 누락된 확인 항목을 해소한 뒤 배포 파일 한 개로 정리한다.

현재는 1단계에 앞선 상세 설계 도출까지 완료하는 범위다. 실제 운영 자료가 없는 항목을 검증 완료로 표기하지 않는다.

## 승인된 시각 구성 개선
- 단일 세로형 HTML을 유지하고, 포스코 블루 표지에 요청에서 보고서로 이어지는 구성 예시를 배치한다.
- 장별 이모지·번호·블루 색상 띠와 목차의 3개 묶음으로 읽는 흐름을 구분한다.
- 실제 캡처의 원본은 유지하고 HTML 안내 번호와 설명을 덧붙인다. 메뉴 캡처는 확대 영역과 조작 경로를 함께 제시한다.
- 요청의 여섯 요소는 번호형 구성, 요청 개선은 전후 비교로 보여준다.
- 짧은 팁에는 이모지를 제한적으로 사용한다. 문제·퀴즈·정답 선택형 활동은 추가하지 않는다.

## 후속 확정: 정보 밀도
- 본문 글자 크기(데스크톱 18px, 모바일 16px)와 교육 내용을 유지하면서 장 제목, 표, 카드, 단계, 안내 박스의 여백을 축소한다.
- 넓은 화면의 본문 영역을 늘리고 Skill·MCP 조회, 보고서 구성, 파일 확인은 설명과 캡처를 나란히 배치한다. 모바일에서는 한 열로 읽는다.
- 전체 화면 캡처는 미리보기 크기를 제한하고 확대 시 FHD 원본을 제공한다. 단일 세로형 가이드만 유지한다.


## 최신 편집 방향 — 시스템을 설명하는 교과서
이 절이 기존 표지·도입 기획보다 우선한다. 표지는 요청과 자료 → P-Harness 작업공간(모델·Skill·MCP) → 대화와 산출물의 관계를 실제 참고 화면과 함께 보여준다. 도입에서는 읽는 방법과 구성요소를 설명하고, 경쟁사 보고서 미리보기는 08장 활용 예시로 이동한다.

13장 순서와 상세 설명은 유지한다. 핵심 장은 정의와 역할을 시각화한 뒤 실제 화면·조작·상세 표로 설명을 이어간다. 모델은 두 가지 설정 비교, Skill은 작업 유형 분류, MCP는 정보원 가지 구조, 자료 연결은 인식 확인을 거치는 흐름, 산출물은 파일 유형으로 표현한다. 그림의 항목을 누르면 관련 상세 항목으로 이동한다.

제작 소스는 build.py, visuals.py, textbook.css이다. 기존 CSS와 JS를 포함해 최종 p-harness-guide.html 한 파일로 빌드하며 별도 가로판·밀도 모드는 생성하지 않는다. 모델 가격과 제공 상태는 원본 자료 기준, 화면은 MyHarness 참고라는 구분을 유지한다.
