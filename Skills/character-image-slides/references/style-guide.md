# 스타일과 구도

먼저 `../assets/style/preferred-001-coding-agent-experiments.png`를 연다. 큰 남색 손글씨 제목, 코랄 강조, 주인공의 작업과 도구의 상호작용, 사물과 짧은 문구를 연결한 설명 밀도를 참고한다. 이 이미지의 옛 얼굴이나 특정 UI를 새 사실로 복제하지 않는다.

## 화면 문법

- 표지: 제목과 대표 캐릭터 장면을 크게 사용하고 설명을 줄인다.
- 작업 사례: 중앙의 작업을 중심으로 짧은 관찰·변화·결과를 연결한다.
- 구조 설명: 중심 플랫폼·도구·문서와 연결 관계가 먼저 읽혀야 한다. 인물은 관계를 설명하거나 사용한다.
- 비교: 공통 기준을 유지한 두 장면으로 차이를 보인다. 장식보다 비교 항목을 대응시킨다.
- 시간/반복: 시간축이나 순환 경로는 실제로 순서나 반복이 있는 내용에만 쓴다.
- 마무리: 핵심 메시지 또는 질문 공간에 시선을 모은다.

정보가 많으면 주된 장면의 시선 흐름에 라벨과 짧은 설명을 붙인다. 의미 없는 카드 그리드로 바꾸지 않는다. 모든 장에 인물을 같은 크기로 넣을 필요는 없고, 복잡한 구조도에서는 작은 사용 장면만으로도 캐릭터 연속성을 유지할 수 있다.

원본 일부의 작은 라벨과 고밀도는 참고의 한계다. 새 덱에서는 발표 환경에서 읽힐 크기를 확보하고, 필요하면 문장을 줄이거나 상세 내용을 발표자 노트로 옮긴다. 확정 원고나 장수와 충돌하면 누락을 숨기지 말고 조정이 필요한 지점을 설명한다.

## 스타일와 정체성의 우선순위

현재 사용자 지정 > 현재 캐릭터 시트(정체성) > 선택한 스타일 참조(선화·색·밀도) > 옛 제작 결과 순이다. 서로 다른 역할의 참조를 섞어서 옛 주인공 얼굴을 현재 얼굴 대신 쓰지 않는다.

번들 캐릭터는 일반 업무 장면에서 7.4등신, 유머나 시행착오 장면에서 5등신을 선택할 수 있다. 축소형은 단순히 전체 그림 크기를 줄이는 방식이 아니다. 같은 장면에서 이유 없이 비율을 오가게 하지 않는다. 모든 조연을 매번 넣지 말고 역할에 맞는 인물만 선택한다.
