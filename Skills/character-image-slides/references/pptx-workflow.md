# 이미지 덱 패키징과 검증

이미지 제작을 완료한 뒤 적용한다. 이미지형 PPTX는 제목과 도표까지 이미지 안에 있으므로 텍스트와 도형의 개별 편집, 텍스트 검색을 보장하지 않는다. 편집 가능성이 명시된 작업에서는 해당 요구에 맞는 혼합형 또는 편집형 제작 방식을 우선한다.

## 순서와 입력 계약

`output/slides.json`에 다음과 같이 명시적 목록을 기록한다. 이미지 경로는 목록 파일 기준이며 실제 순서는 배열 순서다. 파일명이나 생성 시각으로 순서를 추정하지 않는다.

```json
{
  "width": 1920,
  "height": 1080,
  "slides": [
    {"id": "intro", "image": "images/slide-001.png", "notes": "이 장의 발표 내용과 출처"},
    {"id": "workflow", "image": "images/slide-002.png", "notes": "이 장의 발표 내용과 출처"}
  ]
}
```

제작 전에 모든 경로의 존재, 이미지 디코딩, 실제 크기·종횡비, 빈 목록, 중복 ID, 의도하지 않은 중복 이미지, 요청 장수와의 일치를 확인한다. 오류가 있으면 부분 덱을 완성품으로 내보내지 않는다. 기존 PPTX와 원본 이미지는 덮어쓰지 않는다.

## PPTX 구성

현재 환경에 프레젠테이션 제작 스킬이 있으면 해당 구현과 내보내기 지침을 읽는다. Codex 데스크톱에서는 `load_workspace_dependencies`로 번들 런타임을 확인하고 `@oai/artifact-tool`을 사용한다. 런타임 절대 경로를 이 스킬에 고정하지 않는다. 환경에 해당 도구가 없으면 사용 가능한 PPTX 라이브러리를 확인하되 이미지 삽입 계약을 그대로 유지한다.

- 슬라이드 크기를 입력 이미지와 같은 비율로 설정한다. 라이브러리의 픽셀·포인트·EMU 단위를 혼동하지 않는다.
- 빈 레이아웃을 사용하고, 각 장에 완성 이미지 하나를 좌상단 `(0, 0)`부터 슬라이드 전체 폭과 높이로 삽입한다.
- 비율이 다른 이미지를 늘이거나 제목을 잘라 채우지 않는다. 이미지 보정 단계로 돌아가거나 사용자가 요청한 여백 배치를 적용한다.
- 이미지를 외부 파일 링크가 아닌 내장 미디어로 저장한다. 불필요한 재압축을 피한다.
- 생성 이력과 검증 로그는 노트에 넣지 않는다. 필요한 발표 원고와 사실의 출처를 발표자 노트에 넣는다.
- 이미지 교체 때는 목록의 해당 항목만 교체하고, 같은 목록으로 다시 빌드한다.

## 최종 검증

1. 최종 이미지 전부를 실제로 열어 문구와 캐릭터를 확인하고, 몽타주로 색감과 구도 반복을 점검한다.
2. PPTX ZIP의 `ppt/presentation.xml`에서 슬라이드 장수와 크기를 확인한다. `p:sldIdLst`와 관계 파일을 따라 실제 발표 순서를 읽는다. `slide1.xml` 등의 파일명 순서를 발표 순서로 가정하지 않는다.
3. 각 슬라이드의 이미지 관계가 내장 미디어로 해석되는지, 순서대로 올바른 최종 이미지가 들어갔는지 확인한다. 이미지 SHA-256가 원본과 같으면 원본 바이트 보존의 증거다. 재인코딩한 경우 해시 불일치를 숨기지 말고 실제 디코딩 결과를 비교한다.
4. 완전 이미지형의 경우 슬라이드당 그림 하나, 좌표 `(0,0)`, 슬라이드 크기와 동일한 영역, 불필요한 crop·회전·추가 텍스트가 없는지 확인한다. 미디어 수는 이미지 재사용 시 장수와 다를 수 있으므로 그것만으로 실패라고 하지 않는다.
5. 내보낸 최종 PPTX를 다시 열거나 렌더해 전 장을 확인한다. 생성 전 미리보기만 확인한 것을 최종 PPTX 검증이라고 부르지 않는다. PowerPoint에서 직접 확인했다는 표현은 실제로 그렇게 했을 때만 쓴다.

패키지 검증과 시각 검증은 별개다. 순서·크기·미디어 검사가 통과해도 한글 오탈자나 인물 정체성이 검증된 것은 아니다. 실패/미검증 사항은 `output/validation/`에 기록하고 최종 응답에 사용에 영향을 주는 한계를 알린다.
