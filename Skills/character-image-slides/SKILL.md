# 캐릭터 이미지 슬라이드

큰 손글씨형 제목, 일관된 캐릭터, 업무 장면과 설명 도식을 한 화면에 통합한 이미지형 발표자료를 만든다. 기본 스타일은 인창원 특강의 쿨화이트 오피스 웹툰이다. 완성 이미지 한 장이 PPTX의 슬라이드 한 장이 된다.

## 시작과 저장

- 현재 사용자의 원고, 등장인물, 디자인, 장수, 출력 형식이 아래 기본값보다 우선한다. 장수에는 표지와 마무리도 포함하며 임의로 늘리지 않는다.
- 이 저장소에서는 새 제작 주제에 `Projects/<주제>/input/`과 `output/`을 만들고, 요구사항과 원본은 `input/`, 원고·프롬프트·이미지·PPTX·검증 기록은 `output/`에 저장한다. 같은 주제의 후속 작업은 기존 폴더를 사용한다. 다른 저장소에서는 그 저장소의 저장 규칙을 따른다.
- 스킬 개량 요청만으로 새 덱이나 유료 시안 이미지를 생성하지 않는다.
- 이 폴더 전체를 복사하면 참조 자산을 함께 재사용할 수 있다. 원본 프로젝트나 다른 스킬의 자산 경로에 의존하지 않는다.

## 필요한 참조만 읽기

1. 제작 전 [스타일과 구도](references/style-guide.md)를 읽고, 그 문서가 지정한 기본 스타일 이미지를 실제로 연다.
2. 번들 인물을 사용할 때 [캐릭터 인덱스](references/characters.md)와 해당 인물 시트를 연다. 사용자 지정 캐릭터가 있으면 그것을 우선한다.
3. 이미지 생성에는 [프롬프트 양식](references/generation-prompt.md)을 사용한다.
4. PPTX가 필요하면 [이미지 덱 패키징과 검증](references/pptx-workflow.md)을 따른다.
5. [자산 출처와 해시](references/asset-manifest.json)는 출처 확인용이다. 생성할 때 전부 읽거나 모든 이미지를 모델에 첨부하지 않는다.

## 기본 시각 계약

- 캔버스는 16:9, 목표 해상도 1920×1080이다. 실제 파일의 크기를 확인하며 프롬프트에 적었다는 이유로 FHD라고 보고하지 않는다.
- Cool White 또는 순백 바탕, Graphite·Deep Navy 선화, Steel Blue 연결선, 제한적인 Coral·Orange·Teal 강조를 사용한다. 배경의 누런 종이·세피아와 사진 같은 피부 질감은 기본값에서 제외한다.
- 깔끔한 한국 오피스 웹툰 인물과 절제된 셀 채색, 가벼운 펜 스케치 업무 배경을 조합한다. 인물은 생각하고 만들고 설명하고 검토하는 행동으로 내용에 참여한다.
- 상단 제목, 중심 설명 장면, 필요할 때 하단 요약으로 읽기 순서를 잡는다. 사물 라벨·짧은 대화·도식으로 정보 밀도를 확보하되 작은 글자로 원고를 밀어 넣지 않는다.
- 매 장 같은 좌측 박스, 타임라인, 로봇을 복제하지 않는다. 시간 흐름, 비교, 구조, 반복 개선 등 내용의 관계에 맞춰 구도를 고른다. 중앙 제본선이나 양면 만화 규칙을 적용하지 않는다.
- 얼굴·헤어·연령·기본 체형·복장을 유지한다. 번들 주인공의 현재 시트가 옛 선호 슬라이드의 얼굴보다 우선한다. 사용자의 다른 등장인물 설정을 인창원 인물로 바꾸지 않는다.

## 제작 흐름

1. 원고를 슬라이드별로 정리한다. 각 장에 `id`, 제목, 핵심 메시지, 정확한 화면 문구, 등장인물, 장면/관계, 근거, 이미지 파일명을 기록한다. 원고가 확정 문구이면 그대로 보존한다. 인창원 자료는 스타일 참조이며 그 날짜·성과·제품 화면은 새 주제의 사실이 아니다.
2. 장면을 설계한다. 하나의 지배적인 설명 장면과 필요한 보조 요소를 고른다. 문서 묶음·서가·업무 책상 같은 비유는 설명을 돕도록 사용하고, 실측 데이터나 실제 UI처럼 제시하지 않는다.
3. 이미지 생성 도구에 스타일 참조와 등장인물 참조의 역할을 구분해 전달한다. 로컬 이미지는 먼저 열어 본다. 새 캐릭터만 있는 경우 반복 등장용 정체성 기준부터 정한다.
4. 제목·라벨·짧은 대사·그림을 포함한 완성 슬라이드 이미지를 생성한다. 이 이미지형 스타일에서는 그림과 글자를 함께 완성하는 것을 기본으로 한다. 텍스트 오류는 해당 영역의 그림과 문구를 함께 편집하거나 해당 장을 재생성한다. 사용자 요청 없이 가림 상자나 중복 글자로 덮지 않는다.
5. 장마다 원문 대조와 시각 검사를 한다. 긴 한글 문장, 숫자, 영문 약어, 화살표 방향, 말하는 사람, 인물 연속성, 잘림을 확인한다. 실제 UI·로고·정확한 표가 필요하면 원본을 보존하는 별도 구성을 사용하고 이미지로 지어내지 않는다.
6. 최종 이미지 경로를 명시적 순서 목록으로 확정한다. 숫자 이름을 문자열 정렬해 `1, 10, 2` 순서로 만들지 않는다. 수정 장은 그 위치만 교체하고 나머지 순서는 보존한다.
7. 이미지형 PPTX를 만들고, 내장 이미지와 최종 파일 렌더를 검증한다. 이미지형 PPTX의 본문·도표는 개별 편집이 안 된다는 점을 전달한다. 편집 가능한 도표가 명시적으로 필요하면 혼합형 구성을 따르고 차이를 설명한다.

## 완료 기준

- 요청된 장수·순서·원고가 맞고, 모든 이미지의 문구와 캐릭터를 실제로 확인했다.
- 전체 몽타주에서 색감과 반복 인물이 일관되며, 발표 크기에서 제목과 핵심 정보가 읽힌다. 고밀도 참조의 작은 글자를 그대로 답습하지 않는다.
- PPTX에 그림이 실제로 포함되고, 각 장이 알맞은 비율로 채워지며, 재열기/렌더에서 누락·잘림이 없다.
- 최종 PPTX와 필요 시 최종 이미지 폴더를 링크한다. 시각 검증이나 PowerPoint 확인을 수행하지 못했으면 정확히 밝힌다. 이미지 생성 도구가 없으면 원고와 프롬프트까지만 제공하고 완성 덱으로 보고하지 않는다.
